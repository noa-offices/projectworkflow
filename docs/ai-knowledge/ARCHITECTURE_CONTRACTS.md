# Architecture and contracts

Read the existing [architecture](../ARCHITECTURE.md), [database](../DATABASE.md), [workflows](../WORKFLOWS.md), and [overview](../PROJECT_OVERVIEW.md) for context. These are historical guides: their coverage of inventory and newer supplier pricing is incomplete. Source and migrations on the current branch govern actual implementation; deployed migration state is **NOT VERIFIED**.

- App routes and server actions call shared logic; [auth guards](../../lib/auth.ts) and [access decisions](../../lib/auth-access.ts) coexist with database RLS. Preserve both; do not infer database access from UI visibility. See [server client](../../lib/supabase/server.ts), [types](../../lib/supabase/types.ts), and [migrations](../../supabase/migrations/).
- Product templates, components, materials and pricing feed quotation configuration. [Template snapshot](../../lib/quotations/product-template-snapshot.ts) and [quotation workspace](../../lib/local/quotation-workspace.ts) define distinct boundaries: inspect them before altering saved item behavior. Exact propagation of every product edit to existing quotations is **NOT VERIFIED**.
- Local builder publication uses a snapshot, base version and mutation ID, with an atomic database check in [route](../../app/api/quotations/%5Bid%5D/local-workspace/route.ts) and [migration](../../supabase/migrations/20261001093911_local_builder_atomic_publication.sql). A version probe is only a hint. Preserve conflict and retry semantics.
- Supplier price identity/version contracts start at [contracts](../../lib/products/supplier-price-contracts.ts), [version helper](../../lib/products/pricing-write-version.ts), and [foundation migration](../../supabase/migrations/20261002060146_pricing_identity_version_foundation.sql); inspect subsequent migrations for current rules.
- Integrated inventory uses schema `inventory`, its own tables and RLS: [schema](../../supabase/migrations/20261023100000_inventory_schema.sql), [initial RLS](../../supabase/migrations/20261023100100_inventory_rls_and_storage.sql), and [later privacy migration](../../supabase/migrations/20261030100000_inventory_privacy.sql). Initial policies alone are not current policy truth.
- NOA session and ResultSet state are scoped handles, not authorization or cached business truth; see [NOA guide](NOA_AI.md) and [CLAUDE.md](../../CLAUDE.md).

Database field-by-field completeness, all policy interactions, storage permissions and cross-deployment state are **NOT VERIFIED** by this audit. Inspect relevant migrations and tests before modifying a contract.
